# Ground relief

The code shows how the pieces are wired. These are the decisions behind it, which the code cannot show.

- The ground relief draws nothing of its own, it changes how other features draw, so its code is split by feature: each feature keeps its relief in its own `Relief` folder (`Camera/Relief`), and `Tile/Relief` holds the core they share (the terrain store, the heights read on the CPU, the frame's datum, the uniform and the shader header every rising draw binds) with the relief of the tile's own ground and buildings. A feature whose relief is a call into the core keeps the call where it is. New relief code goes into the `Relief` folder of the feature it changes, the boundary rules are on `GroundReliefStore`. The core's folder is split by reader (`Store/` the terrain tiles and their loads, `Frame/` what the frames draw by, `Demand/` what the planner asks for, `Lifts/` the heights read on the CPU, `Shaders/` the header), and a new file goes into the folder of the one that reads it. The core is split by what changes it: `GroundReliefStore` holds the terrain tiles and nothing of a frame, loading them from a `GroundReliefTerrainSource` (a new kind of terrain is a new conformance, not a change to the store), and `GroundReliefFrameState` holds what the frames draw the relief by (the rise and the collapse, the datum, the light, the shadows), settled once a frame into a `GroundReliefFrame` value that every feature reads through `FrameContextServices.groundRelief`. The engine knows the relief only as `GroundReliefFrameState`, and a feature draws by the frame's value and never holds the store: the planner alone reaches the store, through `GroundReliefTerrainDemand`, handing over what it planned while the relief works out which terrain that needs. The ground's grid rises by terrain no finer than `GroundReliefSettings.displacementMaximumZoom`, and its slopes shade per pixel by the ring's own terrain (`PlaceTile.displacement`, `PlaceTile.terrain`): the fine terrain is spent on the light, the geometry stays light. The occlusion of the sky (`ImmersiveMapTerrainOcclusion`, `GroundReliefOcclusion`) is computed per terrain tile from its heights, off the main thread, when the tile lands and again when the style changes, and the fragment stages only sample it: a valley darkens at every zoom for the price of one texture read. The relief stands between `GroundReliefSettings.appearZoom` and `collapseZoom`, and collapses earlier where the terrain source has no tile at the zoom the near ring reads under the camera (`collapsesWhereTerrainIsMissing`, decided by the source's 404, remembered for good): Mapterhorn has lidar past zoom 12 only where a country publishes it, and its 30 m cells stretched past their zoom read as hills where there are none.
